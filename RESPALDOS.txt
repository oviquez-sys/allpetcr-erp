========================================================
   ALLPETCR ERP  —  RESPALDOS (COPIAS DE SEGURIDAD)
========================================================

Actualizado: 02/09/2026


========================================================
  EN UNA LINEA
========================================================

Todas las noches a las 21:00 se guarda solo un respaldo de la
base de datos en OneDrive; los domingos a las 21:30 se guarda
ademas todas las fotos. Si algo falla, llega un correo.


========================================================
  LO QUE HAY QUE SABER SIN LEER NADA MAS
========================================================

  · Se hace solo. No hay que acordarse de nada.
  · Se guarda FUERA de esta computadora (OneDrive).
  · Si falla, avisa por correo. No falla en silencio.
  · Se puede recuperar de verdad: hay un ensayo que lo prueba.

Los tres archivos que importan, en la carpeta del ERP:

  RESPALDO_AHORA.bat         Hacer un respaldo ya mismo, a mano.
  PROBAR_RESTAURACION.bat    Comprobar que el respaldo SIRVE.
  PROGRAMAR_RESPALDOS.bat    Volver a dejar las tareas programadas.


========================================================
  COMO ESTA ARMADO
========================================================

Dos ritmos, porque la base y las fotos cambian a velocidades
distintas:

  DIARIO   21:00, todos los dias
           Solo la base de datos: ventas, inventario,
           contabilidad, clientes. Pesa menos de 1 MB.
           Se conservan las ultimas 30 copias.

  SEMANAL  21:30, los domingos
           Base + todas las fotos de productos. Unos 130 MB.
           Se conservan las ultimas 4 copias.

La logica: lo que cambia todos los dias se respalda todos los
dias. Las fotos casi no cambian, y guardar 130 MB diarios
llenaria la nube en pocas semanas.

Como maximo se pierde un dia de ventas.

DONDE QUEDAN:

  OneDrive  ->  AllPetCR_Respaldos\diario\
  OneDrive  ->  AllPetCR_Respaldos\semanal\

Cada ritmo en SU carpeta, a proposito: el sistema borra los
respaldos viejos de la carpeta donde escribe. Si compartieran
carpeta, el respaldo semanal (que conserva 4) borraria los 30
diarios cada domingo.

SI LA COMPUTADORA ESTA APAGADA a la hora programada, la tarea
no se saltea el dia: corre apenas se prende.


========================================================
  QUE PASA SI ALGO FALLA
========================================================

Llega un correo a servicioalcliente@allpetcr.com con el asunto
"[AllPetCR] ...". Ese correo es para leer el mismo dia, no para
dejar pasar.

Hay tres avisos distintos:

  "FALLO el respaldo"             No se pudo hacer.
  "NO paso la verificacion"       Se hizo, pero el archivo no sirve.
  "quedo solo en la computadora"  No encontro OneDrive.

Cada respaldo se revisa apenas se crea:
  1. que el zip abra,
  2. que traiga la base adentro,
  3. que PostgreSQL pueda LEER ese volcado (pg_restore --list),
  4. que traiga las fotos, cuando corresponde.

El registro de cada corrida queda en:
  respaldos\log_respaldo_diario.txt
  respaldos\log_respaldo_semanal.txt


========================================================
  RESPALDAR AHORA, A MANO
========================================================

Doble clic en RESPALDO_AHORA.bat. Revisa el respaldo que hay,
crea uno nuevo y lo vuelve a revisar.

Por comando, con el entorno activado:
  python manage.py respaldar


========================================================
  COMPROBAR QUE SE PUEDE RECUPERAR  (hacerlo cada mes)
========================================================

Doble clic en PROBAR_RESTAURACION.bat.

Agarra el respaldo mas nuevo, crea una base de datos de prueba
aparte, restaura el respaldo ahi adentro, cuenta productos,
ventas y movimientos, y despues borra la base de prueba.

LA BASE REAL NO SE TOCA.

Es la unica prueba que vale. Que un archivo se abra no dice nada
sobre si el negocio se puede recuperar. Esto lo dice.


========================================================
  RECUPERAR DE VERDAD (cuando paso algo)
========================================================

Esto reemplaza los datos de HOY por los del respaldo elegido.

ANTES: apaga el ERP (Ctrl + C en la ventana negra donde corre).
No se puede restaurar con el sistema encendido.

1. Abri el cmd en la carpeta del ERP y activa el entorno:
     .venv\Scripts\activate

2. Mira que respaldos hay. Sin opciones, el comando los lista:

     python manage.py restaurar

   Eso busca en la carpeta "respaldos" de esta computadora.
   Los respaldos automaticos estan en OneDrive, asi que para
   verlos hay que decirle en cual carpeta buscar:

     python manage.py restaurar --destino "%OneDrive%\AllPetCR_Respaldos\diario"

   Cambia "diario" por "semanal" si necesitas tambien las fotos.
   Copia el nombre del archivo que quieras.

3. Primero SIN confirmar, para ver que haria (no cambia nada):

     python manage.py restaurar --archivo "RUTA COMPLETA DEL ZIP"

4. Cuando estes seguro, agregale --confirmar:

     python manage.py restaurar --archivo "RUTA COMPLETA DEL ZIP" --confirmar

   ANTES de tocar nada guarda como esta la base ahora, en la
   carpeta "respaldos". Si restauras el respaldo equivocado, hay
   marcha atras.

   La bitacora del sistema (quien hizo que) NO se pisa con la del
   respaldo: se conserva la de la base viva.

5. Prende el ERP de nuevo.


========================================================
  LO QUE TODAVIA FALTA
========================================================

  · Subida automatica a un lugar que no dependa de OneDrive
    (FRA-005: bucket Backblaze B2 con Object Lock). OneDrive
    protege del disco que muere, pero NO de un borrado ni de un
    ransomware: eso se sincroniza a la nube igual que todo lo
    demas. Hoy la defensa contra eso son las 30 copias diarias.

  · Una copia mensual en un disco o llave USB que no este
    conectada. Guardar SIEMPRE el respaldo del cierre de cada mes.
